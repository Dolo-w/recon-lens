Capability map · recon-lens v0.1.0

一条规则的一生，十五个工具都在图上

同一张图回答两件事：对账跑到哪一步了，以及——这一步是谁在做、用什么在调。 中间是主链路，左边标签写着执行者（人 / Agent / 引擎），右边是这一步能调的 MCP 工具；纯引擎内部的格子会直说「无对外工具」。 起草有两条并行的入口，人写 YAML 和 Agent 一句话生成，最后汇进同一个规则库。

Two doors, one catalog

起草有两条路，落点是同一个

人写 YAML 走 POST /api/rules；Agent 用一句话走 recon_draft_rule，后台 LLM 起草完还要过同一套静态校验和影子试算。两条路产出都是草稿，谁也不能跳过第 3、4 步。

Trial decides, human signs

能不能批，试算说了算

第 3 步只产出「可批性」：验全了免签、采样了要签、验失败谁也不能签。系统里只有第 4 步这一次人签字，而且绑定内容哈希——签完又改，等于没签。

Streaming, not loading

内存与数据量无关

第 6 步两条游标一升一升地推，200 万行 × 2 张表在 -Xmx256m 下跑完、0 次 Full GC。前提是 MySQL 连接带 useCursorFetch=true，否则驱动会偷偷把整表读进来。
