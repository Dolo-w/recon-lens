# 业界知识层收录标准（K5）

> 回答三个问题：什么算「业界知识」？什么内容该收？什么坚决不收？
> 本文是 ingest / distill / seed 三条写入通道共同的上游标准：AI 蒸馏 prompt 内置其中红线，机器准入（admit）执行其中可机械校验的部分，其余靠本文评审时对照。

## 1. 定义：什么算「业界知识」

**跨客户成立的、与对账差异归因相关的领域先验。** 三个判据，缺一不收：

1. **跨客户** —— 是行业普遍现象，不是某一家客户的配置或某一次事故的孤例；
2. **归因相关** —— 能指导「遇到这类差异，先查什么」，能落到 appliesWhen 条件上；
3. **方向性** —— 引导排查顺序，**不替引擎算数**。知识短句永远不参与金额计算。

与归因知识库（diff_kb）的分工：diff_kb 存「经验」（本系统跑出来的归因结论，精确键控）；业界知识层存「先验」（行业共识，条件谓词匹配）。客户特定的事实既不进业界知识层（不跨客户），也不进 diff_kb（无键控形状）——那属于客户配置，走规则版本与数据快照。

## 2. 该收什么（按优先级）

| 优先级 | 类型 | 例子（seed 已有） |
|---|---|---|
| 1 | 普遍根因模式：跨厂商成立的计费/对账病 | 舍入误差累积、时区 epoch 误读、元/分单位、幂等重试、cut-off 时点、NULL vs 0 |
| 2 | 厂商特有行为陷阱 | Lago 作废发票仍出现在导出、credit note 是冲销凭证 |
| 3 | 口径差异知识 | 先折后税 vs 先税后折、归属期 vs 出账期、阶梯边界含/不含端点 |
| 4 | 新计费形态的先验 | token 取整口径、GB 二进制/十进制（AI 计量计费场景） |

## 3. 坚决不收（红线）

1. **客户特定配置**：「这家客户先付后赠」——客户知识，不跨客户，且入库即泄漏客户信息；
2. **精确数字断言**：「费率 0.15」「封顶 5 万」——会过时，更会被误当计算依据。本系统原则：规则引擎算对，LLM 和知识层都不算金额；
3. **瞬时事实**：「某厂商上月发布了 X 功能」——没有归因价值，三个月后是噪音；
4. **教程 / 营销 / 新闻稿** —— 无差异归因密度，只会稀释注入预算；
5. **与差异归因无关的通用知识** —— 怎么部署 Lago、怎么写 SQL，不收；
6. **与库内高置信条目冲突且无法仲裁的** —— 先走冲突标记，不直接入库。

## 4. 文档来源分级（喂 ingest 之前先看这个）

- **A 级（优先喂）**：厂商官方计费/API 文档（Lago、Orb、Stripe billing docs 等）、行业标准（ISO 4217 货币单位、IANA 时区库）。事实密度高、可溯源、稳定。
- **B 级（可喂，需清洗）**：事故复盘、技术博客里「我们怎么对平 300 万差异」这类一手经验、GitHub issue 归纳。含金量高但夹叙夹议，靠蒸馏 prompt 的红线过滤。
- **C 级（不喂）**：营销材料、新闻稿、客户内部文档（非普遍 + 涉密风险）、AI 聚合站二次内容（无一手出处）。

## 5. 好条目五标准（每条可检验）

1. **有适用条件** —— appliesWhen 至少一个维度非空（fieldRegex / diffTypes / directions）。无条件条目对每条差异生效=常驻加税，机器准入直接拒；
2. **方向性启发式** —— 写「先查 X」不写「X 即答案」；写「通常、优先、先对齐口径」这类概率语言；
3. **短** —— text 一句 ≤120 字，注入有字符预算封顶，长句挤压别的条目；
4. **可证伪** —— 核销反馈能判出采纳/改判（客户 note 复述该结论=采纳，改判=驳回）。写完问自己：什么样的客户反馈能证明它错了？答不出来就别收；
5. **有出处** —— source 字段可追溯到 A/B 级来源或 seed 人工审定。`lago-api-2026-11` 这种带版本戳的来源格式。

## 6. 生命周期（标准之外，机制兜底）

- **准入**：机器校验结构 + 条件非空 + 去重（`IndustryKbService.admit`）；
- **起点置信度**：HUMAN 0.9 > SEED 0.7 > LLM 生成 0.5——信任梯度即来源分级；
- **注入分层**：≥0.6 直接注入 / 0.3-0.6 带「AI 生成·低置信」标注 / <0.3 不注入；
- **涨落**：核销反馈采纳 +0.05、改判 -0.1；<0.2 自动进 graveyard 停止注入；
- **老化**：vendor 语义摘录变更（`ColumnProfiles.semanticsDigest`）触发相关条目重蒸馏；零命中条目进 coldEntries 报表，人工看一眼决定去留。

## 7. 质量保障与已知的未验证项（如实）

- 生成侧：DISTILL prompt 内置第 3 节红线（客户特定/精确数字/瞬时事实不收）；
- 入库侧：admit 结构校验 + 去重；
- 上线侧：采纳/改判核销闭环是知识质量的**金标准**——业界共识（RAGAS faithfulness / 影子模式 / 分级人审四道关）中我们已落生成红线 + 效果闭环两道；
- **未验证**（诚实清单）：① 端到端真实语料 ingest 从未跑过（管道首验待做）；② quote 机械校验（蒸馏条目强制带原文摘录，admit 校验摘录存在于源文本）未实现——这是挡「模型编造出处」的零 LLM 成本手段；③ 管道健康指标（解析成功率/丢弃率/校验通过率）未暴露。三者都是后续小任务，做完才算闭环。
