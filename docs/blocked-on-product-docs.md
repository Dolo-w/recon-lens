# 待办：需要你提供的产品输入

> 这个文件是给你的清单，不是给我自己的。每一项都写清「要什么内容 / 为什么卡住 / 不给时我用什么默认值」。
> 不给也不影响我现在开工 —— 我会用默认值继续，等你的文档到了再回头校准。

## 优先级：不阻塞开工，但会影响验收口径

## 1. 角色与权限矩阵（卡 M2 / M3）

**要什么**：一张表 —— 哪些 operator / 角色能调 `/api/recall/search?mode=` 这类评测接口，哪些只能走正常检索；以及「写动作」的完整清单（改规则、建规则、跑对账、导入文件、提交审批，还有没有别的）。

**为什么**：M3 要给 `?mode=` 加开关，开关挂给谁得先有角色定义；M2 的澄清判据是「带实体的写动作」，写动作的边界得由你划，不能我从 `ChatIntent` 枚举反推。

**不给时我的默认值**：评测接口默认全关（`force-mode-enabled=false`），写动作按现有 `ChatIntent.isWrite()` 的 6 个枚举。

## 2. 口径认定规则（卡 M4）

**要什么**：一句话级别的规则 —— 会话里「谁说的话算数」。具体：用户在聊天里确认的参数算「已确认」还是「待审批」？换个会话又提到同一个 key，算新口径还是覆盖？

**为什么**：M4 要把结论板渲染成带 `[已审批] / [已确认] / [草稿]` 的 JSON，这三档的业务含义必须你定，否则模型看到的权威等级和实际审批流对不上。

**不给时我的默认值**：沿用 ADR D5 的 HUMAN/0.9、LLM/0.5，聊天里的确认记「已确认（未审批）」。

## 3. 工具话术（卡 M6）

**要什么**：14 处「下一步：recon_xxx」里，哪些是给**人**看的提示、哪些是给**模型**看的建议。如果要对外暴露，需要一个统一句式（例如"要继续可以查试算状态"）。

**为什么**：M6 要把它们从工具正文挪进 `ToolSpec.suggestion`，挪出去之后是「会话侧念给人听」还是「MCP 侧也给模型看」，是产品决定 —— 后者会诱导模型串步。

**不给时我的默认值**：只给会话侧用，MCP 工具正文不再出现「下一步」。

## 4. 典型会话样本（卡 M7 验收）

**要什么**：20 条真实业务对话（脱敏），覆盖：长规则体、长差异清单、多轮改口径、跨会话追问。带「期望结果」。

**为什么**：预算五桶（facts 1200 / history 1500 …）砍哪里最不痛，只能拿真实话压。我自己造的会话压不出真实的长尾。

**不给时我的默认值**：用 `docs/chat-test-report.md` 的会话 + 我造的 5 条极端样本。

## 5. 自动续跑的边界（卡 M10，最重要）

**要什么**：一份「哪些动作允许模型自动接着做、哪些必须停下来等人」的白名单。我的建议：读操作可续跑，写操作一律停；但「查差异 → 看归因」这种两连读要不要一次问完，得你定。

**为什么**：循环一旦能串步，风险的形状就从「问错了」变成「连着问错三次」，而且中间没人拦。这条不给，我只能保守到"只允许一次续跑且仅读动作"。

**不给时我的默认值**：一次请求最多续跑 1 步，仅限读动作，写动作一律停在 `pending`。

## 6. 检索可信度排序（卡 M12）

**要什么**：案例（上次怎么处理的）、手册（制度怎么规定的）、全文（文档里出现过）三者谁最可信。现在的权重是 0.7 / 0.3 / 0.5，是我拍的。

**为什么**：M12 要做归一化，权重得有个业务依据，否则归一化只是把"拍的"变成"归一化后拍的"。

**不给时我的默认值**：手册 > 案例 > 全文（0.5 / 0.4 / 0.3），因为手册是制度、案例是个人经验。

## 7. 容量与规模（卡 M14）

**要什么**：生产最大表规模（行数、字段数）、允许的最大分片数、单任务 SLA。

**为什么**：M14 要给 `shard.count` 加上限（默认 256 是我猜的）。放太松闸门形同虚设，放太紧会拦掉合法的宽表分片。

**不给时我的默认值**：256，且只在 `AGENT` 来源的起草里校验，人手写规则不拦。

## 8. 评测问题集（卡 M17）

**要什么**：20 条真实用户问题（脱敏）+ 期望答案 + 判定人。最好区分「P0 就能答」「需要模型」「需要记忆」三类。

**为什么**：这是评测 CI 的基线。没有它，`golden-set-report` 只能证明"能跑通"，证明不了"改好了"。

**不给时我的默认值**：从 `chat-test-report` 抽 20 问，只做回归不做提升对比。

## 9. SLO 与成本上限（卡 M15）

**要什么**：一次会话的 P95 时延目标、单次对账 Agent 运行的 token 预算上限（钱）、多少算"贵"。

**为什么**：M15 要往 step 表加 `latency_ms` / `tokens_est`，但"超标"的定义得你给，否则这两列只是数据不是信号。

**不给时我的默认值**：只记账不告警，报告里我自己标"这条看起来慢/贵"。

## 10. 规则治理流程（卡 M18 / 批 6）

**要什么**：影子试算失败时，业务希望"改这条规则"还是"新建一条规则"？谁有权决定？改过的规则要不要留旧版本可回滚？

**为什么**：M18 的 re-plan 要在两条路里选，选错了会把"该改的规则"做成"重复的新规则"，规则库半年就烂。

**不给时我的默认值**：先尝试改（保留旧版本快照），失败两次后建议新建，最终由人拍。
